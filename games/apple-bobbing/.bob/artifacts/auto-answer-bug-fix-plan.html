🐛 Auto-Answer Bug — Fix Plan

3-phase plan · Permanent removal of all auto-answering code

Root Cause — Identified

There are two separate pieces of code that auto-click answers, and they are both firing incorrectly:

1. watchForRepeatedQuestions() — This was added to skip questions you'd already answered correctly. It watches the quiz card and if the question text matches anything in seenQuestions, it auto-clicks a wrong answer after 150ms. The bug: seenQuestions sometimes contains entries from the current game (not just previous games), causing it to auto-click on questions you haven't repeated at all. The logic is too aggressive.

2. watchAnswers() — the data-sounded flag not clearing correctly — When a wrong answer is clicked, the button gets data-sounded="1" to prevent the sound playing twice. But the MutationObserver fires multiple times per class change, and in some edge cases the flag is not cleared before the next question appears — causing the observer to think a new answer was just selected and firing sounds/logic again.

The fix is straightforward: completely remove watchForRepeatedQuestions(). The "no repeat questions" feature is impossible to implement cleanly without access to the game source code, and the auto-click approach is causing more harm than the problem it was trying to solve. Removing it entirely stops all auto-answering permanently.

🙋 One question for you

  1. No-repeat questions feature: The auto-skip was added because you originally asked for "no repeated questions." Since removing it is the fix, are you happy to drop that feature entirely — meaning a question you've answered wrong can reappear later in the same game? The game engine already handles this naturally (wrong answers go back in the deck and come around again at a lower point value). My recommendation: yes, drop it — the game already penalises wrong answers with fewer points, which is the right mechanic.
Phase 1 Remove watchForRepeatedQuestions() entirely ~5 min · quickfire.js

Delete the entire function and its call from DOMContentLoaded. This is the primary source of auto-clicking.

What gets removed
  • The watchForRepeatedQuestions() function (~18 lines)
  • The seenQuestions Set and all references to it
  • The seenQuestions.add(prompt) call inside watchAnswers()
  • The seenQuestions.clear() call inside resetSession()
  • The watchForRepeatedQuestions() call in DOMContentLoaded
What stays intact
  • All sound hooks (correct/wrong sounds still fire on real player answers)
  • QF round trigger counting (still counts correctly answered apples)
  • Green bubble/tint on wrong answers
  • All other session reset logic
Phase 2 Harden the MutationObserver in watchAnswers() ~15 min · quickfire.js

Make the answer observer bullet-proof so it can never fire sound or count logic more than once per question, regardless of how many times the DOM mutates.

Current fragile pattern
  • Uses data-sounded attribute on buttons to de-duplicate, but this attribute is cleaned up when the quiz card hides — there is a race condition where the cleanup fires before the observer has finished processing
  • The observer fires on every class change on any answer button — if the bundle adds/removes classes rapidly it can fire multiple times
Hardened pattern
  • Use a module-level let questionHandled = false flag (not a DOM attribute) — set it to true the moment a right or wrong answer is detected, and only reset it when the quiz card becomes hidden again
  • This is a single boolean in memory — it cannot be affected by DOM mutation timing or race conditions
  • The observer checks if (questionHandled) return as its very first line
Phase 3 Verify & test ~10 min

Confirm the fix works across the scenarios that were causing the problem.

Test scenarios
  • Answer a question wrong twice → correct on third attempt — no auto-answering should occur at any point
  • Answer a question correctly → next apple → answer wrong — sounds should fire correctly, no auto-click
  • Play Again after a full game → answer questions in new game — no carry-over behaviour from previous game
  • Quick Fire round fires mid-game → return to normal quiz → answers work correctly
